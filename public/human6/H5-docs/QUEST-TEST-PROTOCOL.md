# Quest 3 acceptance protocol — pending hardware execution

This is a test procedure, not a completed headset certification. No Quest was connected during development. A browser cannot force an unsupported display rate. Prefer the supported 72 Hz mode (13.89 ms/frame); use the runtime-reported rate and its actual budget.

1. Serve the complete `human5/` directory at an HTTPS origin. Record Quest/browser version, refresh rate, battery/charging state, renderer resolution, ambient temperature, actor count and quality tier. Clear microphone permission once to test the first-run path.
2. Enter VR and allow microphone access. If the permission prompt consumed activation, tap Enter VR again. Confirm the status reaches Listening, then Hearing, Transcribing and Replying. Test five spoken turns, TTS interruption/muting, a denied permission retry, exit/re-entry, and a missing network/server. First local model download is a separate startup test; record its duration. Check that microphone tracks stop after leaving VR.
3. Warm the scene for two minutes. Stand in the cul-de-sac and turn your head continuously; approach Mira and each house. Repeat after 15 minutes of normal use to expose thermal throttling. Do not infer performance from a cold, stationary menu.
4. Export the performance report while in XR at the end of each scenario below. The rolling report retains 720 intervals (about ten seconds at 72 Hz), not the entire session. Save multiple exports. Use `human2.performanceController.exportReport()` through remote debugging if the headset download UI is inconvenient.
5. Test: close face while speaking; two-hand NPC pulling and recovery; two-hand rug stretching/cutting; couch/mattress damage; six burning props including foam; carried and tipped torch contact; water entry/exit; driving across grass/curbs/slopes; wheel damage and repair; returning from each original scene to the cul-de-sac. Keep two actors/pets visible where the original controls permit it.
6. For each export inspect delivered interval p50/p95/max, missed-frame fraction, CPU p95, GPU p95 when available, calls, triangles and detail tier. Timer availability must not be confused with a zero GPU cost. Include all hitches; annotate startup/pause separately, never silently remove them from raw evidence.
7. Proposed release gate: at least 98% of steady-play intervals within 1.38× the supported frame budget, no sustained half-rate delivery, and p95 CPU/GPU work below 85% of that budget after thermal soak. At 72 Hz that work target is about 11.8 ms. This is a proposed quality gate, not a result achieved in the container. Investigate any sustained drop below 60 delivered frames/s even if the chosen refresh is higher.
8. If CPU misses: inspect actor/contact timing first, then furniture/pets. If GPU misses: compare lower foveation/detail tiers, overdraw, mirrors/portals and shadows. Test one controlled change at a time. Reduce pre-session framebuffer scale only between sessions. Keep hand, steering and nearby contact updates responsive.

Record a short screen capture for visual regressions, but measure again with capture disabled because recording may affect cost. A passing mono desktop test does not replace this protocol.
